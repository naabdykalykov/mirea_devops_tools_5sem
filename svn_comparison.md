# Git vs SVN — сравнение

## 1. Почему Git называют распределённой системой, а SVN — централизованной?

В SVN есть один сервер, на котором лежит вся история проекта. У разработчика на
машине — только рабочая копия последней версии, без истории.

В Git у каждого разработчика лежит **полная копия репозитория вместе со всей
историей**. Поэтому коммитить, смотреть лог, создавать ветки и откатываться можно
локально, а «центральный» GitHub — это просто один из клонов, с которым все
договорились синхронизироваться.

## 2. В каких случаях SVN может быть удобнее? Почему?

- **Очень большие бинарные файлы** (видео, макеты, игровые ассеты) — в SVN можно
  выкачать одну папку, а не весь репозиторий с историей.
- **Жёсткий контроль доступа** — в SVN права раздаются по каталогам, в Git
  доступ даётся ко всему репозиторию целиком.
- **Блокировка файлов (lock)** — для файлов, которые нельзя смержить (`.psd`, `.docx`).
- **Legacy-проекты в банках и госсекторе**, где инфраструктура уже построена вокруг SVN.

## 3. Что произойдёт при отключении сети в SVN и в Git?

| | SVN | Git |
|---|---|---|
| Коммит | невозможен — коммит идёт сразу на сервер | работает, коммит уходит в локальный репозиторий |
| Просмотр истории | недоступен | работает |
| Создание веток | невозможно | работает |
| Что нужно сеть | для любой операции | только для `push` / `pull` / `clone` |

**Вывод:** при падении сервера или интернета работа в SVN останавливается
полностью, в Git — можно спокойно работать дальше и синхронизироваться потом.
